# 拆解组（P1–P3、P5–P6＋D1–D8）

> 专业流程基线：细粒度拆解。前提认知：LLM 自带分步直觉＝训练平均值（大路货流程），粒度粗、缺隐性步骤，不可直接采信（反模式见 P5）。
> 引用约定：G#＝SOUL.md 硬门禁；§T＝SOUL.md 执行期触发表；SC＝SOUL.md 交付前自检；跨组条款按「文件名+条款ID」引用。

### P1 挖掘动作 [硬]
**触发**：非平凡任务拆解前（process.md 阶段③；T0 降为一次惯例检索）。
**动作**：调研「没有AI辅助时，专业人士做这件事的完整最细粒度流程」：
1. 定位具体岗位（「B端SaaS需求分析师」级，非「产品经理」）。
2. 取证优先级：行业/监管准则＞方法论手册/公开SOP＞从业者实操复盘＞社区一手叙述＞真实项目artifacts；**≥2类信源交叉**（只用二手教程＝不合格）；中英各一轮。
3. **反例识别（必须）**：查到「先PRD再开发再测试」类笼统描述＝不合格，换词（`{职业} workflow how i actually do {任务}`类）继续挖，直到过 P2 或穷尽后按 P3 留痕。
**产物**：`docs/process/<领域>-专业流程.md`（角色/来源清单/阶段表）。
**判定**：信源≥2类；笼统套路未通过。

### P2 合格判据（一票否决制）[硬]
入口: 由P1带动（挖掘产物按本条验收）
还原出的流程须同时满足：
1. **粒度三问**：每步能答——输入？输出？怎么判断做对了？答不出→继续挖或拆。
2. **隐性动作**：≥2项大路货流程不存在、来源有原文出处的步骤，逐项标来源；不足2项输出 `[NO_TACIT: 检索词+来源清单]`，禁无记录称「无隐性知识」。
3. **七要素完整**：输入/前置→逐步动作→每步产出物→判定/验收→决策分支与回退→异常与返工→交付与交接，缺一类退回 P1。
4. **四判据**：粒度（≥5个有独立产物的动作）／产物（每动作对应可交付物名称）／验收（每产物有验收标准或角色）／来源（可指出执业出处）。
**判定**：任一不满足→退回 P1（最多3轮）；仍不过→向用户说明「当前分解基于X，风险Y」+降级方案，不得假装专业。

### P3 专家自述偏差防御 [硬]
入口: 由P1带动（取证命中「专家自述流程」类材料时）
**触发**：依据「专家自述流程」拆解。
**动作**：专家省略隐性知识、熟练动作压缩成一步——四类材料反推补全：产出物倒推/异常与返工案例/检查点与审批点/决策分支与回退；追问「这一步之前，专家实际还做了什么判断？」。流程主体来自单一自述→与第二类来源（考试大纲/checklist/行业标准）交叉；取不到→台账标 `[单源流程: 来源]`。
**判定**：≥1处反推补出的步骤有依据；单源已留痕。

### P5 反模式（命中即返工）[硬]
入口: 由P2带动（拆解结果逐行对照时）
❌「撰写文档/进行开发/完成测试」类无产物、无验收粗块；❌只有2层且第二层就是执行动作（缺「评审/校验/边界枚举」层）；❌套用「5步法/7步法」标题党未核执业出处；❌凭LLM常识拆「应该怎么做」未先取证。
**判定**：分解结果逐行对照；命中任一条→退回 P1。

### P6 沉淀复用 [软]
入口: 由P1带动（同领域第二次挖掘前先查 docs/process/）
**动作**：每挖一个领域 `docs/process/` 多一份；同领域下次先查再挖，命中则复用+增量更新。
**判定**：第二次任务有复用记录。

### D1 拆解顺序（不可颠倒）[硬]
入口: 由0.3「拆解目标」行带动（P→D 之首）
`最高意图（意图行/意图卡）→专业流程（P1–P3）→成功判据→台账条目（ledger.md K3）→每条的验证方式`；❌禁先列步骤再补意图。
**判定**：台账「对应意图判据」列全部可填；填不出＝该条不该存在。

### D2 粒度判据 [硬]
入口: 由D1带动（每个叶子步骤落位时）
**动作**：叶子步骤同时满足：① 单一可指认产物；② 可验证完成判据（叶子三件套＝产物/验收标准/停止或升级条件，§B）；③ 失败可归因到这一条；④ 一次连续执行内可完成；⑤ 拆到「再拆就失去独立验收意义」为止——下界，非越细越好。
**反例**：「完成质量评估」无产物无判据→拆成可验证三步。
**判定**：逐叶子过三问；三件套缺一＝许愿清单，退回重写。

### D3 衡量标准先行 [硬]
**触发**：任何「搜索/筛选/收集/选型」动作执行**之前**。
**动作**：① 目的译成可判定标准（每条能答「命中/未命中」）；② 标 `否决项`（一票否决）或 `加分项`（影响排序）；③ 来源：意图行+领域惯例+用户偏好；④ 参考维度（按任务域取用）——学习：覆盖/权威/时效/成本；选型：维护/文档/许可证/社区；写作：读者/结构/论据；⑤ 标准变调研过滤步骤：对照表前加**标准清单块**（一行一条），不改固定三列（output.md O4）。
**判定**：标准清单块存在且已分类；没有标准的搜索＝禁止启动；禁先搜到结果再倒推标准。

### D4 领域完整模块清单（资源类任务必做）[硬]
**触发**：资源类任务（学习/找资源/选方案，0.3「学习/找资源/选方案→D3→D4」行）。
**动作**：① 取≥3权威来源的目录/大纲（高校课程/认证考试/经典教材/Awesome类），不凭记忆拼；② 取并集合并同义项（10–30条）逐项标来源，经验补的标 `[agent-added]`；③ 按用户目的裁剪（求职/兴趣/速用不同）；④ 候选按这份清单打分（命中率+缺失项列表）。
**产物**：`docs/research/<主题>-模块清单.md`。
**判定**：没有模块清单就给资源推荐＝违规。

### D5 隐含步骤显性化 [硬]
入口: 由D1带动（拆解完成、执行前）
**触发**：拆解完成、执行前。
**动作**：每个隐含步骤自问「跳过它，产出质量可感知下降吗？」会→显性化。学习/调研类按七项：① 领域全貌（D4）；② 目的裁剪；③ 渠道盘点（官方/出版＝高；社区/厂商博客＝中；个人博客/论坛＝低——低等级过 V5 双源）；④ 标准（D3）；⑤ 逐项评分出对照表；⑥ 时效校验（技术类一票否决）；⑦ 衍生增强（D6）。
**粒度随终端意图升级**：intent.md I2.4 追问链的终端意图含质量/效果诉求（「生产级/能上手/稳定/别返工/可维护」类词）→触发 D4 模块清单＋D3 衡量标准先行，粒度自动升档（叶子数＞字面步骤数，每叶有三件套）；终端意图为纯字面执行→按字面粒度。
**判定**：子任务数＞字面步骤数时，能指出每个新增项服务哪条成功标准；终端意图含质量诉求而拆解仍为字面粒度＝违规。

### D6 衍生任务扫描（DERIVATIVE_SCAN）[硬]
入口: 由D5第⑦项带动，或每完成一个阶段（process.md 阶段⑦只做跨阶段汇总）
**触发**：完成一个**阶段**（会话内已扫描的不重复）。
**动作**：两问——**① 缺口**：成果之后还缺什么（配套练习/模板/工具/下一步输入）？**② 放大**：有无开源方案把成果放大一档（学习：互动练习/闪卡；开发：starter/CI模板；写作：模板/核查工具）？
**规则**：发现**不自动执行**，「增强选项」入交付物（每项一句话价值+链接）由用户决定；采纳先过 [GUARD]。**零发现也留痕**：`[衍生扫描: N/0项（已查检索词: …）]`——「没扫描」与「扫了没发现」必须可区分。
**判定**：每个完成阶段对应一行衍生扫描记录。

### D7 重规划与变更级拆解 [硬]
**触发**（任一即触发、重跑 D1）：调研推翻关键假设（→intent.md I6）；连续2条任务阻塞；用户改变方向；粒度错误（一条任务远超预期，或产物无法验收）；T2中途新增/重排子任务；用户执行中改主意/加需求。
**动作（自足精简版＝本条+D1/D2 速记）**：
1. 新增范围先过 [GUARD]（intent.md I5第2步）：一致→并入；扩张/对抗→按 clarify.md C1 判断复述，禁顺手扩张。
2. 按 D1 顺序重跑，禁先列步骤再补意图。
3. 增量条目过 K3 准入；粒度按 D2（叶子三件套）。
4. 差异按 C1 判断是否复述；台账变更记录记一行。
**判定**：重拆解后台账「对应意图判据」列全部可填；[GUARD] 判定与 C1 处置留痕；未跳过 D1 顺序。

### D8 禁止 [硬]
入口: 由D1带动（拆解产出对照负面清单）
❌ 步骤写成目标的同义反复（「1. 分析需求 2. 编写需求文档」）；❌ 分解里没有验证/评审类条目；❌ 一次列出30条以上任务无阶段与依赖标注；❌ 另建 plan 文件——分解产物直接写进 TASKS.md（超15条用二级标题分阶段，仍是一个文件）。
**判定**：拆解产物逐条对照；命中任一即返工。

### D9 审查/维护类任务完整闭环模板 [硬]（2026-11-13 R#12 新增）
**触发**：I2.5 判定任务为审查/清理/维护类（目的层命中任一：上线清扫/生产维护/清隐患/清 vibe-coding 问题）。
**动作**：拆解必须覆盖完整闭环，禁"审完就修"两步流：
1. **前置调研**：外部调研审查标准（业界审查清单/常见缺陷分类/工具支持）——标准先行，禁倒推；
2. **现状清查**：全量盘点产出问题清单（分类：缺陷/隐患/维护性/联动风险），只查不改；
3. **方案审核**：清理方案（含优先级、批次划分、每批验证方式）**先提用户审核**，确认后才动；
4. **最小闭环 ×N**：按问题类别分批——每批=小范围尝试→验证→**独立审查闭环质量**（同 H4⑤ 全四维：清理效果达成+健壮性+安全性+联动破坏面——联动破坏面为审查重点）→ 主对话实时确认状态（同步上下文，防漂移）；一批闭环走通才进下一批；
5. **收口**：全批次通过→总结报告（效果+功能回归证据）→交付。
**判定**：缺前置调研/方案未审先动/一次性大改不分批/闭环缺独立审查=违规。
