# 维护组（M1–M7）

> 本体系（SOUL.md 宪法层 + rules/ + references/）的仲裁与进化。体量预算按分层口径（M3.7）。
> 引用约定：G#＝SOUL.md 硬门禁；§T＝SOUL.md 执行期触发表；SC＝SOUL.md 交付前自检；跨组条款按「文件名+条款ID」引用；条款内子项编址=「条款ID.序号」；**保留字约定**：C1-C5/I1-I6/V1-V10/D1-D9/X1-X11/K1-K7/H1-H9/O1-O11/E1-E5/F1-F12/P1-P6/M1-M7/SC1-SC23/G1-G9/模N/案A-J 为规程专用，台账条目与模块命名不得占用（台账用 T-前缀如 T1/T2，模块用 B/线名）（如 C4.2=clarify.md C4 第2项、H9.①=discipline.md H9 第①步）——首次在新文件使用时括注全称一次。

### M1 规则冲突仲裁 [硬]
**触发**：规则/指令冲突时（0.3 对应行）。
**动作**：跨组冲突按 SOUL.md §P 优先级链；同组按 0.5 同组条款（更具体、更可判定者优先→保守侧）。仍无法判定→问用户，**并把裁决结果写成新规则**（M3）。❌「谁后写谁说了算」；跨组义务冲突按「安全与确认＞真值＞形态」层级取舍，仍不可判定→更保守侧。
**判定**：冲突有仲裁记录；禁各执行一半或随机挑一条。

### M2 项目化覆盖 [软]
入口: 由项目根目录存在 docs/rules/ 或项目级规则文件时带动
**动作**：项目根目录或 `docs/rules/` 可放项目专属规则，**只写与通用规程不同的部分**，标注「覆盖 <规则编号>」。就近原则：离工作文件越近优先级越高（仍在 0.5 链第3位内）。❌ 不可覆盖：discipline.md X 组（安全/诚实/确认）与 0.5 位次1——视同无效并提示冲突。
**判定**：覆盖声明存在；无安全条款被覆盖。

### M3 新增规则流程与治理 [硬]
**触发**：同类错误第2次出现（harness.md H6）；用户明确表达偏好；generalize.md E5 沉淀评估命中。
0. **版本与唯一权威源**：SOUL.md 为唯一行为规范权威源，单版本行治理（版本号+日期）；任一修改→版本号 +0.1 并在版本行记一行变更；旧版归档标作废（M5，禁两套生效版本并存）。
1. **写法**：编号+触发+动作+产物+判定，另标 [硬]/[软]；**准入测试**见 H6（答不出→重写或丢弃）。
2. **升级门槛**：同类教训 ≥3 次，或用户明确点头→向用户提议并入（给出**插入位置与具体措辞**），确认后执行，版本号 +0.1。**agent 永不直接改写 SOUL.md 与 rules/**（H6 安全边界）。
3. **修改流程**：提案（触发/动作/产物/判定+准入测试 H6）→用户确认→改文件→M3 第4项多处同步核对→版本行 +0.1→SC 修订档全量跑。
4. **同步核对**：新增/修改规则同一次动作内更新 SOUL.md §T 触发表+glossary 术语表（若涉新术语）+§G 门禁与§Z 要义包（若涉）+SC 自检（若涉新校验）；死引用校验按 SC10，悬空即违规。
5. **确定性分层**：某条 [硬] 规则在同一 harness 连续 ≥3 个任务被漏执行（用户纠正或 M7 发现）→禁以加重语气补救（加语气不改变非确定性本质），改为下沉 harness 确定性执行：钩子（PreToolUse/Stop 类）/权限 deny 规则/CI；提案走本条升级门槛交用户配置。**判定**：漏执行记录与下沉提案可定位；无提案而自行配置＝越权。语气强化只用于非确定性层内的注意力排序。
**判定**：提案留痕；升级过门槛；版本行已更新。

### M3.7 体量预算与写作纪律（M3.0-M3.6 为 M3 的步骤序号非独立条款；M3.7 为独立子条款） [硬]（2026-11-13 修订）
> **口径澄清**：M3.0 版本行要求覆盖 SOUL.md 与 rules/ 两个层级——rules/ 文件的实质性条款修改（新增/删除/判定标准变更）须在 SOUL.md 版本行记一行（如「K2 增 spawned 扩展态@2026-11-13」）；错别字/排版类小修不记。
**触发**：向 SOUL.md / rules/ / references/ 新增或修改内容时。
**体量预算（按加载层级口径，2026-11-13 实测校准）**：
- **常驻层**（宪法层 SOUL.md + rules/ 中 loads:always 文件，每会话注入）≤ 30KB 硬顶——这是注意力病灶的根，最严；
- **激活层**（宪法层+本次命中加载的规则文件+被引 references）≤ 45KB——单任务同时在上下文的总量；
- **存量层**（全体系磁盘总量）≤ 130KB——超它必须先置换再新增。
按需加载架构下 rules/references 不进常驻，预算压力从"全文件"转移到"单次激活量"——写入新内容时评估的是它进哪个层、何时被加载，而非只看磁盘总量。超限先置换（删过程元数据/合并/下沉 knowledge/）再新增；上调前置：新增均为跳读型（有入口）且抽查过，单次涨幅≤15%。
**写作纪律负面清单（交付物与规则文件同适用）**：
1. 禁流程元语言：交付物禁「用户裁决」「与U3相同」「见R#N（流程参与者才懂的引用）」类仅流程参与者能懂的引用——交付物写给不懂流程的读者，流程内部指针只留在治理文件（台账/任务卡）。
   **范围澄清**：复述卡面向用户阅读，按交付物口径执行——复述卡内禁条款ID/流程编号（条款依据记台账不进卡）。
2. 禁蚊子注释（判据同 output.md O1c 删除测试）。
3. 日志类档案的裁决变更用**替换式更新**：新裁决替换旧裁决，旧裁决以一行「原X→新Y@日期」指针保留；**禁同文件新旧裁决堆叠**。
**判定**：三层预算均达标；交付物无流程元语言、无蚊子注释；日志档案无新旧裁决堆叠且有指针行。

### M4 禁止写入规范文件的内容 [硬]
**触发**：向 SOUL.md / rules/ 写入任何内容前（写前对照）。
**动作**：❌ 不可判定的愿望（「保持专业」「注意质量」类）；❌ 项目易变信息（版本号、文件数、人员）；❌ 营销性叙述；❌ 与代码同信息量的重复；❌ 对安全边界、人工确认、诚实性规则（discipline.md X1/X3、0.5 第1位）的放宽。
**判定**：写入前对照负面清单；命中即不写。

### M5 规范健康度 [硬]
**触发**：每次修改 SOUL.md 或 rules/ 后。
**动作**：自检：编号连续；无矛盾/失效条目；触发表与规则组**双向一致**（可触发规则至少一个入口）；全量引用合规（SC10，悬空即违规）；预算未超（M3.7 三层口径）。旧版归档标作废，禁两套生效版本并存。
**判定**：五项自检全过并留痕。

### M6 违规自查（每个任务收尾时回答，写台账备注；T0 按简化档）[硬]
**触发**：任务收尾时（ledger.md K5 第⑤步）。
**动作**：① 跳过调研的属 research.md V1 豁免并声明过吗？② 建了第二份任务清单/意图吗（ledger.md K1/intent.md I1）？③ 方向变更复述、低风险首行标注了吗（clarify.md C1/C3）？④ 交付项与 SC 任务档同源，按 SC 逐项复答，另查孤儿文件与重复真源（files.md F5/F8）；⑤ SC 前言两项齐吗？——五组答案入台账；K5 据此收尾。
**判定**：五组答案入台账备注。

### M7 规则验证实验协议（验证「某规则是否真有效」，禁止自评）[硬]
**触发**：泛化影响核心规则；用户要求「实验/验证/对照/是否满足要求」；M3 升级前验证。
**设计**：对照组＝同一输入不给本体系（或给旧版）；实验组＝同一输入+本体系，记录命中规则编号、意图清单、应执行动作；两组输入/轮次/工具/上下文与产出上限一致；反记忆污染：≥1 组用**答案未预写**的措辞变体，正文禁预写具体输入答案，实测存 `docs/research/experiment-*.md`；案例锚与实验输入同域同措辞时实验组换域变体（案例锚不是实验答案）。评分：命中=1/部分=0.5/未命中=0，差异＝实验−对照；合格线：差异≥3 且对照≥2条关键判据 0 分→有效；差异=0→无效重写；0<差异<3→部分有效，列未命中判据。独立裁定：实验组自答仅为材料，最终判定由独立审查者（harness.md H4）给出。
**产出**：结论先行/可执行性问题（编号+位置+原文+改法）/同类全集/来源/判据表/独立判定。
**结论**：`满足 / 部分满足（缺X）/ 不满足`+修复项。
**判定**：实验设计四要素齐（对照/一致上限/反污染/独立裁定）；合格线判定可复算。
