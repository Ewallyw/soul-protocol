# 台账组（K1–K7）

> 任务台账与多会话状态；K1–K7，勿与任务分级 T0/T1/T2 混淆。
> 引用约定：G#＝SOUL.md 硬门禁；§T＝SOUL.md 执行期触发表；SC＝SOUL.md 交付前自检；跨组条款按「文件名+条款ID」引用。

### K1 唯一性 [硬]
**触发**：任何任务开始/任何多会话场景。
**动作**：一个项目根**有且只有一份** `TASKS.md`（+ T2 的 `INTENT.md`）；多会话、多子代理、多分支全读写这一份；harness 自带 todo 只是会话内工作副本，**会话结束前必须同步回台账**。**发现多份任务清单**：① 停建新任务文件；② 差异条目合并进 TASKS.md（保留原描述+来源）；③ 其余移 `archive/superseded-tasks-YYYYMMDD/`；④ 报告用户。分工：**台账管任务状态，任务卡管启动产物与原话，互不复制**（process.md S.0d）。
**判定**：`find . -iname "*todo*" -o -iname "*task*"` 结果中任务清单类文件只有一个（archive/ 除外）。

### K2 台账模板与状态机 [硬]
入口: 由K1带动（台账创建/更新时）
**动作**：状态机（封闭六值+1扩展态）：`blocked → todo → doing → verify → done / dropped`；**并行派发态 `spawned`**（子代理运行中未回收，回收后转 doing/verify/blocked）——spawned 不占 doing 配额，但同一意图行下 spawned+doing 总数 ≤3；同一时刻 `doing` **最多 1 条**（主对话亲自推进的条目）；进入 `verify` 才允许写 `done`（discipline.md X3 证据）。**心跳行（每 3 工具轮次一行）**：`轮次#N  ctx:相关度=高/低,待释放={块名}  intent:主线判定=推进/漂移`（ctx 来自 harness.md H1，intent 来自 intent.md I5，一次更新双查；轮次计数随工具调用写台账，不靠记忆）。**[GUARD] 判定行**：触发与格式见 intent.md I5第2步，结构性更新版本首行必带。
**判定**：doing ≤1（spawned 不计）；spawned 条目必须在心跳行标注回收时限（超 2 个心跳周期未回收→查子代理状态）；心跳行连续两个区间 intent=漂移→触发 discipline.md X4 评估。

### K3 条目准入（全部满足，否则拆或改）[硬]
入口: 由decompose.md D1带动（台账新增条目时）
**动作**：① 叶子三件套齐（单一产物/可验证判据/停止与升级条件——decompose.md D2）；② **挂意图**（对应意图判据列填成功标准编号，同 D1）；③ **粒度**（≤1 工作单元，超出按 D 组拆）。
**判定**：三条件全过才入台账；任一不过→拆或改。

### K4 更新时机（事件驱动，不靠自觉）[硬]
**触发**：事件发生后**立即**更新台账，禁「稍后一起」：新增/删除任务；状态跃迁；发现阻塞；用户改变方向；调研推翻假设（intent.md I6）；子代理返回（结论摘要入条目备注）；**每 3 工具轮次**（心跳行，K2）；每阶段完成。
**判定**：事件与台账更新零延迟（同一动作内）；无「稍后一起」。

### K5 会话收尾与交接 [硬]
**触发**（任一）：上下文消耗 ≥70%；harness 告警；一个阶段完成；（T2 项目）会话结束。
**收尾清单（七步）**：① 台账更新到真实状态（doing→正确状态、证据列填写）；② INTENT.md 更新 `updated`/`review_due`；③ 可复用结论落盘（research.md V9/files.md F9），单会话任务写复盘卡；④ `scratch/` 清理（F7）；⑤ meta.md M6 自查+SC 任务档；⑥ 交接卡（七字段：任务ID/会话/日期、阶段、已完成（证据指针）、未完成（断点: 已完成X/剩余Y/下一步第一动作）、阻塞、下一步、意图卡原文、命中规则编号）；⑦ 收尾汇报（output.md O1a）：完成什么（带证据）/差什么/需用户决策什么/文件路径。
**落盘五项**：① 进度标记；② doing 条目断点（已完成X/剩余Y/下一步第一动作）；③ 决策记录；④ 开放问题；⑤ 告知用户已落盘。无法自测余量→每完成一个叶子步骤即落盘。
**判定**：一个没看过对话的新会话，只读 INTENT.md+TASKS.md+交接卡（或任务卡）就能继续干活——做不到＝交接失败。

### K6 冲突与中断 [硬]
入口: 由discipline.md X6 归类「冲突/取代」行带动（台账侧状态处置时）
**触发**：新请求与台账开放任务冲突/取代时。
**动作**：默认中断并放弃（条目移「已放弃」注明原因）；仅当用户明确「继续/恢复」才恢复。分工：discipline.md X6 管行为，K6 管台账状态；中断未恢复＝blocked，明示放弃＝dropped；用户更正归类（「不是取代，是都要」）→恢复 todo 并留痕；整任务废弃→旧条目 dropped，半成品清单报用户三选（保留/归档/删除）。**中断时挂起动作联动**：被打断前最后一个落地动作属部署/提交/发送类→按 process.md S.0a 挂起召回条款记台账 `挂起: 动作+触发条件`（此时条目状态＝blocked，等待触发条件）。
**判定**：冲突条目状态已改且留原因行。

### K7 执行期接手 [硬]
**触发**：执行中发现非 agent 操作痕迹——用户手工改动、外部工具产物（时间戳异常/格式不一致/台账外文件）。
**动作**：① **先读后动**：逐个读其现状与来龙去脉再动手，禁直接覆盖；② 理解不了的标 `[未理解: X]` 询问用户，不强求全知——已知未读、未知臆测都违规；③ 以现实为准修正台账/任务卡并留痕；④ 痕迹处置记台账一行。
**联动**：新会话/跨会话接手既有任务的前处理走 process.md S.0e 三步；中断消息归类走 intent.md I1/discipline.md X6。
**判定**：痕迹处置留痕一行存在；无「未读直接覆盖」。
