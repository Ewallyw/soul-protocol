# 协调组（H1–H7、H9）

### H1 上下文敏感（每3轮自检）[硬]

入口: 由ledger.md K2 心跳行带动（每3工具轮次入 `ctx:` 三题），或触发词「同一文件第2次完整读／单条工具结果≥3000字／心跳欠账3轮」
**触发**（任一）：同一文件第2次完整读/单条工具结果≥3000字/心跳欠账3轮（ledger.md K2）。
**动作**：大段原始输出→摘要外置留路径+一句结论（research.md V9）；关键中间信息→复诵（process.md LC1）；无关历史→不回读、定点读；阶段切换→重读意图行+只读 SOUL.md §0 与命中条目。三题入 K4 心跳行 `ctx:`：相关度（<一半→压缩或派子代理）/待释放大块/久未重申的约束。
**判定**：上下文增量只来自必要新信息；同一原文段落二次完整粘贴即违规。

### H2 派发判定（子代理普遍化；本组派发权威源）[硬]

**派发总则（默认派）**：

1. **审查默认派**：语义判断类产物（方案/文案/命名/拆解质量/对外措辞）一律派独立审查，禁自审自证——**主对话验证自己的修改＝无效验证，升格硬规则**。小任务用**轻量快审**：派单只给 ① 判据基线（代码/截图/预期效果）② 用户需求或 LLM 理解的意图 ③ 禁附主对话推理过程；回收 ≤3 行结论。
2. **调研默认派**：L2 及以上（research.md V7 分级）一律派子代理，主对话只做 L0/L1 点查。
3. **成本分模块**：调研类放开深度广度预算（L2/L3 按模块预算，深度广度优先）；产出类收紧输出形态（按 clarify.md C3 首行+output.md O8 交付形态，禁倾倒过程）。
4. **后台运行辩证条款**：探查类任务禁后台运行——后台探查的中间结论会带偏主线判断；执行类（跑测试/长构建）可后台。是否后台不改变派发判定，只改变运行方式。
5. 除上述外，派发判据沿用规模（>3文件/>200行/>3章节）／隔离（子任务独立可验证且台账并行≥2）／并行（无依赖多任务）／探索性（可能整体废弃）。
6. **不派**：单点小查（V1 L1档）；需与用户多轮交互的澄清；依赖主线隐性上下文的判断；任务很小（派单开销>收益）。
7. **并发卫生**：同一文件写入**必须串行**（并行＝竞态/覆盖/匹配失败）；不对同一限速主机并发（外部写节流见 H5）；长任务每完成一个叶子步骤即落盘（增量进展+干净环境）；不轮询等待——给足等待或先做独立工作。
   **产物**：派发判定行（派/不派+一句理由；语义判断产物附加轻量快审单据）。
   **判定**：语义判断产物无独立审查记录＝违规（自审自证升格硬规则）；L2+ 调研无派发判定＝违规；探查类跑后台＝违规。

### H3 派单六要素（产物必须落盘约定路径+回收时验落盘回执——本轮实验G-6实证：方案仅在子代理返回值中、未落盘即派审查=审查两手空空，此为硬项）与回收 [硬]

**触发**：按 H2 判定「派」后。
**派单六要素**（单据，缺一即违规）：目标+为什么/上下文（不假设主对话可见）/输入物/边界（不许碰什么/工具范围/禁止项）/返回格式+验收/预算+超限动作（超限即停，返回结论与阻塞点）。
**委派前自检**：重读派单书问「如果我失忆，只凭这段话能一次做对吗？」——不能就重写（多数 harness 无追问通道）；每个形容词问「执行方能据此做出不同决策吗」，不能即删或换可验证标准（「尽量精简」→「≤3条」）；歧义高危附好坏示例各一（示例约束力大于形容词）。
**回收只接受**：`结论（≤3行）/证据（路径:行号或URL+日期）/不确定项/建议下一步（≤2条）/产物路径`；超出丢弃并要求重发；中间过程不回主线。
**主agent责任（必须）**：① 子代理结论是待验证材料——采纳前在台账引用≥1条亲自复核的证据并标复核方式（重跑/重读来源/抽查一行），无复核记录＝采纳无效；② 不委派理解——跨结果综合、冲突裁决、最终结论主agent亲自做并写入台账，禁 based-on-your-findings 式转手。
**判定**：六要素齐；台账有复核留痕与亲自综合记录。

### H4 独立审查执行细则（触发位＝H2第1项）[硬]

入口: 由H2带动（语义判断产物/高影响结论成形时）
**触发矩阵**（入口统一在 H2；本条不再单独定义触发，判据词汇与 H2 一致）：① 语义判断类产物（方案/文案/命名/拆解质量/对外措辞）；② 结论影响用户决策/投入较大；代码>50行；敏感数据或删除/对外发送路径；③ 对外发布、上线前；大任务交付前（≥3阶段）；②③由 H2 规模/探索性判据带动；④ 用户质疑/同一问题2次未修好/要求验证；⑤ 自证式严谨——生成器与校验器共用同一规则（校验无效，discipline.md X10）。
**审查规则**：审查者只拿**产物+评判标准+原始需求**，不给主对话推理过程；派单语固定「只找问题，不复述优点」。输出＝问题清单（按严重度）+放行/回退建议；审查证据（截图/日志/输出原文）中**可见的范围外异常**（图片错位、字体重叠、报错、脏数据）一并入清单，标 `[范围外]`+现象与位置——**审核范围≠证据范围**；五问逐条答「是/否+证据」：① 断言有源、相关没当支持、推测没当结论？② 判据逐条满足、未违背非目标？③ 人类3分钟能看懂（O组）？④ 无缺证据的完成声称、治理合规？⑤ **隐性维度（重中之重，R#12 升格为派单硬项）**：健壮性（异常输入/边界）、安全性（注入/越权/密钥泄露）、维护性（可读性/耦合/复用）、**联动破坏面**（本次改动是否破坏既有功能/相邻模块/契约——用户原话：改A组件时截图里可见的B错位也是审核重点）。**派单时**：判据基线必须含四维各自的基线证据（现状代码位置/截图/既有契约），缺维=派单违规；**回收时**：结论必须逐维答「查过+证据」或「未涉及+原因」，缺任何一维=审查无效整体退回重派。**非代码任务**（选型/文案/方案类）：逐维答「不适用+原因」，不许静默略过——适用性判定本身是审查者职责。主agent对每条意见写处理结果（修复/不修+理由），禁静默忽略，处理记录随交付物。生成与校验分离见 SOUL.md 门禁 G8／discipline.md X10。
**降级条款**：无子代理→新开独立上下文则用之；不可得→交付物显著标 `[未独立审查: {原因}]` 并附审查清单与标准交用户；T0 自查标 [T0 自查]，不计入独立审查，禁把自查记为「已独立审查」。
**判定**：独立审查记录存在（审查者/判据/发现数/逐项修复状态）；触发情形无记录即违规。

### H5 能力探测与找轮子 [硬]

**触发**：每会话首轮（能力探测）；非平凡动作（>10行代码/>3条命令/外部系统调用）前（找轮子；纯格式转换与单行命令不触发）。
**能力探测**（[CAPABILITY_CARD]入台账，本会话不重复）：子代理（Task/.claude/agents/dispatch→H2–H4）；技能库（skills/SKILL.md→找轮子）；MCP（.mcp.json/mcp__）；定时（cron→clarify.md C5）；网络检索（轻量验证→research.md V组前提）；文件持久化（试写再删→files.md F组前提）。
**找轮子**（SEEK_TOOL）：① 查 [CAPABILITY_CARD] 与已装 skills，按 description 匹配**真实任务**；命中→完整读说明后使用，不凭名字猜；多命中→最具体先用，未达声明标准再换；② 没有→开源方案检索（research.md V3）；③ 仍没有→手写，通用脚本登记 `scripts/`，ledger.md K5 复盘提「沉淀为技能/规则」（同一拼装流程复用≥3次必提）。❌禁：有专用能力却手搓；读了说明不按其约束执行；为 skill 已覆盖流程另写一套。
**外部写操作节流**：外部API/平台写入假定有限流——合并写、串行突发、尊重 429/Retry-After。
**判定**：探测记录存在（含「未命中」）；非平凡动作前有找轮子痕迹。

### H6 自优化候选（RSI-lite）[硬]

**触发**：被纠正且指向规则/流程缺陷（纯需求演进只记台账）；同类错误第2次；generalize.md E5 命中；审查发现流程级漏洞；同一提示词模板被否定≥2次（改前改后各跑一次，入候选池）。
**动作**：教训写成**候选规则**（「触发→动作」，可判定），记入 `knowledge/lessons_pending.md`（files.md F9）。验证有效的提示词模板沉淀 `knowledge/prompts/` 供复用迭代（每次复用即再校准）。**准入测试**：能答「违反它时怎么被机械地发现？」——答不出＝愿望非规则，重写或丢弃；升级与安全边界见 meta.md M3。
**判定**：候选规则可定位；准入测试可答；无自评通过。

### H7 递归改进边界 [硬]

入口: 由H6带动（候选规则升级为正式规则时）
**动作**：每次只改**一处**规则，观察下次同类任务再保留或回滚；新增一条→查同组可合并/删除的旧规则（规则也会腐烂）；单一偶发事故不写特例（同一事故第2次才规则化）；❌禁改：安全边界、人工确认、诚实性（discipline.md X1/X3）、身份与权限。
**判定**：单次修改一处；无安全条款被改动。

### H9 报错排障（DEBUG_TRIAGE）[硬]

**触发**：用户报告报错/异常/失败。
**动作**：① **先取完整错误原文与复现条件**（日志原文、触发操作、环境），禁凭口头转述直接行动；② 用户的病因假设按 I6第5条 先验证（或低成本试探并标「假设验证」），结论落上下文后才作修复依据；③ 定位后修复，修复后**回归验证**（原场景+相邻场景）；④ 再做**同类穷举**：该报错是否是一类问题的点名项（按 generalize.md E3第2步，在代码/配置范围排查同类隐患）。
**判定**：错误原文在上下文中；回归验证有输出；同类穷举有留痕（含0项）。
